## Recommendations for Future Runs

### Skill Naming Strategy

**Decision tree for skill naming**:
1. Is there an existing umbrella skill covering this domain? → Patch existing skill, add reference file for this paper
2. Is the paper introducing a specific named model/architecture? → Create dedicated skill if model is notable, otherwise umbrella
3. Is the paper a methodology/benchmark? → Create technique-class skill (e.g., "benchmarking-X-strategies")
4. Is the paper an application/survey? → Add to existing domain skill, don't create standalone

**Examples**:
- "Benchmarking positional encoding for EEG" → `benchmarking-positional-encoding-neural-signals` (technique class)
- "MIRAGE model for multimodal encoding" → `multimodal-brain-encoding-methods` with `references/arxiv-2605-29850-mirage.md` (umbrella + session detail)
- "Survey of EEG foundation models" → Add to existing `eeg-foundation-model` skill, don't create new

### Pipeline Automation Opportunities

1. **Automatic skill consolidation check**: Before creating skill, search for similar existing skills (keyword overlap >50%)
2. **Reference file auto-generation**: Extract key findings, code snippets into `references/arxiv-{id}-notes.md`
3. **Git PR automation**: For high-value papers, create PR with review checklist instead of direct push
4. **Knowledge graph linking**: Link skills to each other via "related_skills" in SKILL.md frontmatter
