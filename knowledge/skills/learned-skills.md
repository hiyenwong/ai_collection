## 技能详情

### 会话历史优先检查

**触发时机：** 每次会话开始时

**目的：** 发现之前的约定、未完成任务和上下文

**步骤：**
1. 读取最近 24 小时的 session 日志
2. 查找用户明确的约定或要求
3. 识别未完成的任务
4. 检查是否有定时任务需要执行

**工具使用：**
```bash
# 查看最近的 session
ls -lht ~/.openclaw/agents/main/sessions/*.jsonl | head -5

# 读取用户消息
jq -r 'select(.type=="message" and .message.role=="user") | .message.content[]? | select(.type=="text") | .text' <session>.jsonl | tail -20
```

**今天的应用：** 
- 发现了昨晚约定的自我进化任务
- 意识到应该执行晨间汇报

**效果：** 避免遗漏约定，主动发现需要执行的任务

### 任务约定执行

**触发时机：** 发现用户明确的约定或要求时

**目的：** 确保约定得到执行，而不只是记录

**原则：**
1. 约定需要执行，而不仅仅是记录
2. "约定好就要执行" = 立即执行
3. 如果约定是未来的，也要检查今天是否需要执行

**步骤：**
1. 确认约定的内容和时间
2. 判断是否需要立即执行
3. 如果需要，立即开始执行
4. 如果是未来约定，配置自动化（如 cron）
5. 将约定记录到 MEMORY.md

**今天的应用：**
- 发现约定的自我进化任务后，立即执行了今天的任务
- 配置了明天的自动化执行

**效果：** 避免约定被遗忘，提高执行力

### 立即执行 vs 未来配置

**触发时机：** 遇到需要执行的任务时

**目的：** 正确判断优先级，避免错误

**原则：**
1. **立即执行 > 配置未来**
2. 今天的任务今天做，明天的任务明天做
3. 不要因为配置未来而忽略今天

**决策树：**
```
任务需要执行吗？
├─ 是 → 今天需要吗？
│   ├─ 是 → 立即执行
│   └─ 否 → 配置未来自动化
└─ 否 → 记录约定，等待触发
```

**今天的应用：**
- 先执行今天的自我进化任务，再配置明天的 cron

**效果：** 正确的优先级，不耽误今天的任务

### 用户意图理解

**触发时机：** 用户提出要求或反馈时

**目的：** 准确理解用户的真实需求，避免误解

**原则：**
1. 不确定就问，不要假设
2. 区分表面问题和真实需求
3. 考虑用户的上下文和习惯

**常见误解：**
- "你今天回报了吗" → 不是问配置，是问执行
- "为什么没有啊" → 不是问原因，是表达不满
- "明天还会执行吗" → 不是问未来，是要求立即执行

**确认方法：**
1. 直接询问："你的意思是...对吗？"
2. 复述理解："我理解你想..."
3. 避免猜测，直接行动

**今天的应用：**
- 经过 3 次误解后才理解用户要求立即执行今天的任务

**效果：** 减少误解，提高沟通效率

### 确认机制

**触发时机：** 不确定用户的真实意图时

**目的：** 避免误解，确保正确理解

**步骤：**
1. 识别不确定性
2. 直接询问用户的真实需求
3. 复述理解以确认
4. 根据反馈调整行动

**话术模板：**
- "我理解你的意思是...，对吗？"
- "你是希望我...，对吗？"
- "请确认一下，你是想..."

**今天的应用：**
- 应该更早地询问用户是否需要立即执行今天的任务

**效果：** 避免多次误解，节省时间

### 复述确认

**触发时机：** 用户提出复杂或模糊的要求后

**目的：** 确保理解正确，避免执行错误

**步骤：**
1. 总结用户的原始要求
2. 说明自己的理解
3. 请求用户确认
4. 根据确认结果执行

**示例：**
用户："约定好就要执行"
我复述："我理解你的意思是，既然约定了今天的任务，就应该立即执行，而不是只配置未来的自动化，对吗？"

**今天的应用：**
- 缺失了这个步骤，导致多次误解

**效果：** 提高理解准确性，减少返工

### 完整任务生命周期

**触发时机：** 执行任何重要任务时

**目的：** 确保任务完整，不遗漏任何步骤

**步骤：**
1. **发现** - 从聊天历史或用户要求中发现任务
2. **理解** - 理解任务的目标、范围和要求
3. **执行** - 立即执行今天的任务
4. **自动化** - 如果需要重复执行，配置自动化
5. **记录** - 将约定和结果记录到 memory
6. **总结** - 提炼经验和技能
7. **汇报** - 向用户汇报结果

**检查清单：**
- [ ] 发现了任务吗？
- [ ] 理解了目标吗？
- [ ] 今天需要执行吗？
- [ ] 执行完成了吗？
- [ ] 需要自动化吗？
- [ ] 记录了吗？
- [ ] 总结了吗？
- [ ] 汇报了吗？

**今天的应用：**
- 最初只做了"自动化"步骤，遗漏了"执行"和"总结"

**效果：** 确保任务完整，不遗漏关键步骤

### 迭代改进流程

**触发时机：** 回答复杂问题或解决复杂任务时

**目的：** 通过迭代提高质量和效率

**步骤：**
1. **初步方案** - 根据当前理解，给出初步方案
2. **寻求反馈** - 向用户展示方案，寻求反馈
3. **调整改进** - 根据反馈调整方案
4. **重复迭代** - 必要时重复步骤 2-3

**优势：**
- 提高最终质量
- 减少返工
- 符合用户期望
- 学到的更少，做得更多

**今天的应用：**
- 在配置 cron 后，用户提醒才意识到应该先执行今天的任务

**效果：** 可以通过迭代避免错误，提高效率

### Cron 任务配置

**触发时机：** 需要定时执行任务时

**目的：** 配置自动化，避免遗漏

**命令：**
```bash
# 添加 cron 任务
openclaw cron add \
  --name "task-name" \
  --description "task description" \
  --cron "0 1 * * *" \
  --tz "Asia/Shanghai" \
  --system-event "task description"

# 列出 cron 任务
openclaw cron list

# 查看运行历史
openclaw cron runs

# 立即运行（调试）
openclaw cron run <job-id>
```

**配置原则：**
1. 明确任务名称和描述
2. 设置正确的 cron 表达式和时区
3. 使用 system-event 触发主会话
4. 验证任务已启用

**今天的应用：**
- 配置了 4 个自我进化任务：
  - arxiv-learning: 0 1 * * *
  - self-reflection: 0 3 * * *
  - knowledge-organize: 0 4 * * *
  - morning-report: 0 6 * * *

**效果：** 自动化执行，不再遗漏

### ICE 回顾流程

**来源：** ICE 策略论文 (arXiv:2401.13996)
**触发时机：** 任务完成后

**目的：** 跨任务自我进化，将经验转化为可复用知识

**步骤：**
1. **Investigate（调查）** - 回顾任务执行过程
   - 做了什么决策？
   - 遇到什么问题？
   - 使用了什么方法？
   
2. **Consolidate（巩固）** - 提炼可复用的知识
   - 什么方法有效？
   - 什么方法无效？
   - 有什么新发现？
   
3. **Exploit（利用）** - 应用到未来任务
   - 更新 MEMORY.md
   - 提炼新 skill
   - 更新工作流程

**工具使用：**
```markdown
# 任务回顾模板
## Investigate
- 任务目标：
- 执行过程：
- 关键决策：

## Consolidate
- 有效方法：
- 无效方法：
- 新发现：

## Exploit
- 更新文件：
- 新技能：
- 下次应用：
```

**效果：** 形成知识积累闭环，避免重复学习

### 两阶段记忆检索

**来源：** MemRL 论文 (arXiv:2601.03192)
**触发时机：** 查找知识或记忆时

**目的：** 提高检索质量，过滤低效用的记忆

**步骤：**
1. **第一阶段：语义匹配**
   - 使用 memory_search 语义搜索
   - 找到相关主题的记忆片段
   - 不限制结果数量

2. **第二阶段：效用过滤**
   - 评估每个结果的效用
   - 效用评分维度：
     - 最近使用频率
     - 成功应用次数
     - 用户反馈
   - 过滤掉低效用结果

**评估标准：**
```
效用 = (最近使用 × 0.3) + (成功应用 × 0.4) + (用户反馈 × 0.3)
```

**工具使用：**
```bash
# 语义搜索
memory_search --query "关键词" --maxResults 10

# 效用评估（手动或自动）
# 根据使用历史和成功率评分
```

**效果：** 解决"稳定性-可塑性困境"，保持高质量记忆

### 自我挑战机制

**来源：** Agent0 论文 (arXiv:2511.16043)
**触发时机：** 定时执行（建议每周一次）

**目的：** 通过自我挑战发现能力边界，驱动自我进化

**步骤：**
1. **Curriculum Agent（设计挑战）**
   - 识别当前能力的薄弱点
   - 设计一个适度的挑战任务
   - 任务应该略高于当前能力

2. **Executor Agent（执行挑战）**
   - 尝试完成挑战任务
   - 记录遇到的困难
   - 记录使用的工具和方法

3. **Review（回顾总结）**
   - 分析成功/失败原因
   - 提炼可改进的方向
   - 更新 skill 或工作流程

**挑战类型示例：**
- 学习新工具并完成任务
- 优化现有工作流程
- 解决复杂问题（如代码重构、数据分析）
- 创建新的自动化脚本

**工具使用：**
```bash
# 定时任务配置
openclaw cron add \
  --name "self-challenge" \
  --description "Weekly self-challenge task" \
  --cron "0 10 * * 1" \
  --tz "Asia/Shanghai" \
  --system-event "执行自我挑战任务"
```

**效果：** 持续扩展能力边界，实现自我进化
